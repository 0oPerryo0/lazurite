# Lazurite

An unofficial, read-only chart viewer for the rhythm game **Crystallium**. It shows the charts recovered from the demo build on a 3D perspective playfield, the way they scroll in game. You can scrub, slow down and inspect every note.

> Lazurite is not affiliated with, endorsed by, or connected to Studio Lycanthrope, the developer and publisher of Crystallium. Crystallium, its music, charts, characters and related names belong to their respective owners. This project does not provide the game, scores, saves or account access.

## Features

- **Song catalog**: 21 songs and 63 difficulties (Crescent, Lunar, Astral, Bloodlust, Eclipse), with search by title or artist.
- **Perspective playfield**: taps, slides (holds), bullets and voids, drawn on a Canvas 2D perspective projection of the original track, using the game's own track texture.
- **Playback**: play and pause, seek, playback rate from 0.25× to 2×, scroll-speed multiplier, and jump to an exact timestamp.
- **Audio**: synthesized tap sounds at the judgement line, with separate music and hit-sound volume. You can attach your own copy of a song from your computer; it never leaves your machine. The audio offset is adjustable.
- **Inspector**: live beat and BPM, timing events, and full geometry and timing for any note you click.
- **Settings**: choose whether overlapping slides draw their own outlines or merge into one shape. Stored in your browser only.
- **No build step and no dependencies**: plain ES modules plus a small Node server.

## Quick start

You need [Node.js](https://nodejs.org/) 18 or newer. There's nothing to install.

```bash
node server.mjs
```

Open **http://127.0.0.1:4174/**. Don't open `index.html` directly from disk: the browser blocks the module and data requests.

If port 4174 is taken, set another port:

```bash
PORT=4175 node server.mjs
```

On Windows PowerShell, use `$env:PORT=4175; node server.mjs` instead.

## Using the viewer

1. Pick a difficulty from the catalog to open the chart.
2. Press **Space** to play or pause, and **← →** to seek. Drag the timeline to scrub.
3. Pause and **click a note** to see its data in the Inspector. With the playfield focused, **← →** steps from note to note.
4. Change **Rate** and **Scroll** under the playfield. Tap sounds, timing overlays, the audio offset and local audio are in the Inspector.

## Audio

Charts play silently with tap sounds unless audio is available:

- **In the browser:** use **Attach local audio** in the Inspector to pick the matching song file. It is played locally and never uploaded.
- **Through the local server:** [audio-map.json](audio-map.json) maps chart IDs to audio files in the *parent* folder of this repo. The server only serves files that exist there; in a plain clone none do, so every chart runs silently. These files are never published.

## Hosting

The page only uses page-relative static files: `index.html`, the JS and CSS files, `library.json`, `charts/*.json` and `assets/texture-435.png`. That means it can be served from any static host, such as GitHub Pages, without `server.mjs`.

`library.json` is the catalog. `server.mjs` regenerates it from `charts/` every time it starts, including which songs have local audio. Starting the server on a machine without the audio files therefore changes the audio links in it. Restore the committed version before committing:

```bash
git checkout -- library.json
```

## Project layout

| Path | What it is |
|---|---|
| `index.html`, `styles.css`, `app.js` | The page: catalog, viewer, inspector and settings |
| `engine.js` | Parses the chart format and compiles timing (BPM, scroll changes, beat ↔ time ↔ position) |
| `renderer.js` | Canvas perspective renderer: camera, track, note geometry, paint order, picking |
| `audio.js` | Playback clock with a silent fallback and an audio offset |
| `hitsounds.js` | Synthesized tap sounds |
| `server.mjs` | Local server that binds to loopback only and serves a fixed list of files |
| `charts/` | Chart data: `.json` is what the viewer loads; `.soda` is the original binary, never served |
| `assets/texture-435.png` | The original track texture |
| `library.json` | The catalog manifest, generated by `server.mjs` |
| `audio-map.json` | Local chart → audio mapping, for the local server only |
| `*.test.js` | Node test suites |
| `browser-check.mjs` | End-to-end check in headless Chrome. The Chrome path in it is set for Windows. |

## Testing

The server tests need the local server running. Start it in one terminal:

```bash
node server.mjs
```

Then run the tests in another:

```bash
node --test *.test.js
```

The tests cover chart parsing and timing, renderer projection and geometry, paint order (no notes flashing as they overlap), picking, audio and the server's file whitelist.

## Accuracy

The viewer is a reconstruction from the recovered data, not a capture of the game. Camera, track and note placement follow the original values where they are known. Where they aren't, such as the exact meshes and colours of some notes, the renderer uses documented approximations.
